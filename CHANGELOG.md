# Changelog

History and "why we did X". Operational rules live in `CLAUDE.md`; reference in `docs/`.

## 2026-10-08
- Small masks now generate on an upscaled context crop (`plan_mask_crop` / `crop_mask_work`, `app.py`), in Crop & Composite and Inpainting Pipeline modes alike. Why: a 117x83 px mask on 1376x768 gave klein about 7x5 latent tokens (full-frame inpaint) or a native 192x192 crop, so the area came out as a 16 px mosaic. The crop gets a context margin (50% of the mask side, min 64 px) and is scaled toward 1 MP (max 4x, long side 1536, snapped to /16); the mask is resized with NEAREST; the result is scaled back and composited with the existing blurred-edge paste. Large masks (crop over half the canvas) and auto-outpaint keep their old paths. Verified live on the failing run: the mosaic is gone; the logo still is not placed (klein does not compose a wordmark from a ref at strength 1.0, see the 2026-10-07 tank lesson).
- Fix: transparent PNG refs (logos) were flattened with `convert("RGB")`, which keeps the colour stored under transparent pixels. The Toyota logo PNG stores (35,35,45) there, so the ref became a solid navy rectangle and the model never saw a logo. `core/image_alpha.flatten_to_rgb` now puts a dark logo on white and a light one on dark (opaque images are unchanged); used by `_load_pil`, the single entry for uploaded images. Verified live: the shirt fill changed from dark brown to the ref's new white background.
- Fix: the LTX-Video card in Model Sources had no green "installed" frame and a disabled Download. Cause: `model_sources.json` held a row for the same repo added by Update (`src-116`, name `LTX-Video-0.9.8-13B-distilled`, empty `model_choice`) instead of the seeded `LTX-Video`; the green frame needs `model_choice || name` in the available list, and Download needs the canonical name (the endpoint takes it). `_stored_sources()` now matches an empty-`model_choice` base row to `DEFAULT_SOURCES` by URL and takes its `model_choice` and `name`. Rows with their own `model_choice` are untouched.
- Settings: the HuggingFace login card and the CivitAI key card are one "Accounts & API keys" card at the top of Model Sources (HuggingFace row `HuggingFaceLogin.tsx`, CivitAI row `CivitaiKeyPanel.tsx`, same compact style, divider between). The standalone HuggingFace section is gone; the shared status line (login and model download messages) now sits under the HuggingFace row. Verified in Chrome: one card holds both inputs, no standalone HuggingFace heading, all six base cards green incl. LTX; tsc, build and node tests (68) pass.

## 2026-10-07
- Loading a saved workflow now dims the canvas result (30% opacity + "Previous result, not from this workflow · click to show"). Why: `applyWorkflow` restores params and slots but never touched the canvas, so the last generation looked like the output of the loaded settings. Dimmed rather than blanked so it stays available for comparison. Back to full brightness on a click, on the next result, on Generate, or on Clear. Loading a gallery output (Cmd/Ctrl-click) is not dimmed: the canvas shows that run's own result. State: `resultStale` in the store (`MARK_RESULT_STALE` / `DISMISS_STALE`), set in `handleWorkflowLoad`. Verified in Chrome (gallery load full, saved-workflow load dimmed + badge, click undims); no node test, the reducer cannot be imported under node (extensionless imports).
- Fix: Iterate Masks dropped every unmasked reference. With Inpainting Pipeline on, a mask on the base and a logo in slot #2 (no mask) ran one pass with only `[base]`, so the model never saw the logo and invented one (run `261007-163149`: `workflow.json` listed a single ref slot). Each pass now sends the base, the pass slot's image, then the unmasked refs in slot order (`iterateInputIds`, `src/slots.ts`), so the prompt's "image 2" points at the logo. Behavior is unchanged when every ref has a mask or there are none. Node tests 68 pass, build ok; not yet run end to end in the browser.
- Mask editor: overlay color (6 swatches + custom picker) and opacity slider (5-100%, default 45% as before) in the left column; both remembered in `localStorage` (`maskOverlayColor`, `maskOverlayOpacity`). Why: the fixed 45% red hid on red/orange subjects and was too faint or too strong on others. Display only, the saved mask is unchanged. `paintOverlayRect/Full` now paint the chosen color fully opaque and the editor applies the opacity at draw time (`globalAlpha`), so the slider needs no overlay repaint; a color change repaints the overlay once. New `hexToRgb`. Verified in Chrome (brush stroke recolored green at 90%, values persisted); node tests 65 pass, build ok.
- LoRA dropdown names: no `.safetensors`, underscores as spaces, the CivitAI model name for CivitAI downloads (stored in `civitai_installed.json` as `name`; older entries fall back to the cleaned file name), and the klein size always shown (`70s Sci-Fi Movie · 4B`; the greyed state stays, with its reason as tooltip, the file name is the tooltip otherwise). Why: the extension is identical on every row and pushed the useful part out of the narrow dropdown; the size only showed once a LoRA was already greyed out. `/api/lora/list` gained `display`; `name` stays the identity, so saved workflows and restore are unchanged. Sorting follows the shown name. Also fixed: the LoRA list now refreshes when a CivitAI download finishes after Settings was closed (the row was destroyed before it could signal). Verified in Chrome on the real list.
- CivitAI LoRAs in Model Sources: Update also queries CivitAI (top 100 per base model for klein 9B / 4B / Z-Image Turbo, 275 rows on the first live run), rows sit in the same family folders with a CivitAI chip, size, Download / Installed / Update / Delete, a CivitAI API key field and a "Show NSFW LoRAs" toggle (hidden by default). Downloads go to `lora_uploads/`, verified by SHA256 and a per-family header check, tracked in `civitai_installed.json`. Why: HF alone has few klein LoRAs; CivitAI has hundreds, and about 40% of the popular ones return 401 without a key (measured: 7 of 11 samples), so the key is stored (`civitai/token`, mode 600, gitignored) and sent only to `civitai.com`, never to the storage host it redirects to. Decisions: (1) NSFW is the model flag or version `nsfwLevel & 28`, because the API's `nsfw` boolean is false for R-level LoRAs; (2) the compatibility check is per family, because `check_lora_compatibility` rejects Z-Image keys; (3) the partial file is `.tmp_<name>.part`, because a `.safetensors` temp would appear in `/api/lora/list` mid-download. Verified live on :7861: Update (no NSFW rows stored), anonymous download of `klein_slider_anatomy` (SHA ok, registry entry, reported 9b), no-key 401 shown on the row, UI delete (file + entry gone), NSFW toggle on (493 rows, 218 NSFW) then off + Update (275, 0). Not verified live: an authenticated download (needs the user's own key typed into the UI). Checkpoints are out of scope (app loads diffusers repos from HF, not single-file checkpoints).

Why: the badge number is the image order the FLUX prompt refers to (`image 2`, `image 3`), so fixing a wrong number in a long prompt used to mean removing and re-adding references. Verified in Chrome (ref<->ref swap, drop on itself = no-op, ref onto base still swaps with the base); node tests 56 pass.
- Slot images (base + references): a click now opens `SlotLightbox` (full-size view with pixel size, Esc closes, arrows step through the slots, a Replace button for touch); Ctrl/Cmd+click keeps the old behavior (file picker), as in the gallery preview. Before, any click opened the file picker, so there was no way to see a reference larger than its thumbnail. Verified in Chrome (click, arrows, Esc, Ctrl and Cmd click, Replace button); pure logic `neighborSlot` / `isReplaceClick` in `src/slots.ts` has node tests (54 pass).
- Depth Map dropdown labels: DA2-Large is no longer "fallback" (smooth gradient, the map the RefControl depth LoRA was built around), DA3MONO-LARGE reads "sharp subject edges". Values and default unchanged. Parked idea in `docs/TODO.md`: one-click pose from depth.

Trained on klein-9B Base (guidance 5); the app runs distilled, so results may differ from the author's examples.
- DA3 depth restored: `depth_anything_3` was never declared, so every `uv sync` (exact by default) removed it and the Depth Map failed with `No module named 'depth_anything_3'`. It is now the `depth` dependency group (git source, heavy 3D-export deps excluded, `default-groups` includes it); the lock only gained 7 packages and no existing pin moved.
- Slot badges and the gallery preview thumbs read `img 1 · base`, `img 2`, `img 3`… (were `base`, `ref 1`, `ref 2`), matching how FLUX.2 prompts name images (`image 2` = the first reference).
- Bug pass: server startup trashes `.tmp_uploads/` files older than 24 h (`_prune_temp_dir`).

- Bug pass: Z-Image LoRA load with any failing LoRA now returns a failure status naming them (`zimage_lora_status`), so `ensure_loras_loaded` aborts the generation instead of running with a partial set.
- Bug pass: an LTX video event `info` now says `Saved: <renamed run path>` (it kept the pre-rename path).
- Bug pass: `DELETE /api/output/<run>/...` refuses anything outside `<run>/outputs/` (it used to delete `workflow.json` and `refs/*` on a hand-built request).

Now: (1) `core/model_sources.py` prunes unsupported LoRAs on read (241 -> 73; hand-added entries are `custom` and kept) and Update only adds repos the app can use (file-list check, one `HfApi` call each, in parallel), remembering skips in `ignored`; (2) every row gets a "what it does" line and a function tag, filled automatically from the HF card during Update (and backfilled for existing rows), never overwriting text; (3) the UI shows collapsible categories with counts and nested LoRA family folders with function chips, state remembered. ## 2026-10-02
- Upgraded diffusers git pin (2026-01-15, 0.37.0.dev0) to tag `v0.40.0`; this pulls `transformers` 4.57.5 -> 5.18.0 and `huggingface-hub` 0.36 -> 1.33. Why: Flux2KleinInpaintPipeline, Flux2KleinKVPipeline, a working FLUX.2 small decoder and the native SDNQ backend only exist upstream. Verified over the API against the old stack: FLUX 4B/9B/4B-int8 and Z-Image txt2img, BFL LoRA, ref edit, masked-crop, 4B outpaint LoRA and LTX fast-preview all run with equal timings (4B 18.7 vs 17.8 s, 9B 43 vs 42 s) and the same compositions; same-seed txt2img is not bit-identical across stacks (PSNR 16-27 dB). 108 tests pass. Not verified: Z-Image Full + LoRA (weights not cached). `torch_dtype` now logs a deprecation warning (still works).
- FLUX.2-klein "Inpainting Pipeline (Quality)" now uses `Flux2KleinInpaintPipeline` instead of silently falling back to img2img (the UI used to warn about that; the notices are gone). Why: diffusers 0.38+ ships it, and it blends at the mask edge in latent space, so the faint box seam of crop mode disappears; slots #2+ go in as `image_reference` (a 2-ref run applied the striped pattern of ref 2 to the mug). Built from `pipe.components` (`from_pipe` raises "Casting a quantized model to a new dtype is unsupported" on SDNQ) and cached in `inpaint_pipe`, rebuilt when the klein pipe changes. `padding_mask_crop` is not used: it returned a flat rectangle. Still composited in pixel space (the pipeline drifts ~3/255 outside the mask). Auto-outpaint stays on img2img (the 4B outpaint LoRA is trained for it). Cost: 9B @1024² 194 s (1 ref) / 353 s (2 refs) vs 63 s for crop mode.
- Fixed FLUX -> LTX in one process failing with `'NoneType' object is not callable` (present before the upgrade too): the video branch unloaded the image pipe but left `current_model` and `current_lora_paths` set, so generation took the FLUX branch with `pipe=None`, and a later FLUX request would have skipped reloading its LoRA. Now both are reset there.
